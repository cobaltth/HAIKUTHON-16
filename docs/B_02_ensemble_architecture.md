# B 트랙 ② A·B·C 3단계 앙상블 구조 (가민서)

코드: `submission_ens/model.py`, 빌드: `tools/build_ens.py`, 첫 제출 설정: `submission_ens/ens_config.k15_t840.json`

## 왜 앙상블인가
제출 CSV를 비교해 보니 A(SigLIP+BLIP-2)와 C(SigLIP2+Qwen LoRA)는 서로 다른 답을 냈습니다.
- top-1 일치 22.8%, top-5 평균 겹침 1.87장 (A↔B는 3.44장)
- A·C 중 하나라도 1위를 맞힌 비율은 0.30 이상

CSV를 합치는 건 규정 위반이라, `model.py` 한 개 안에서 질문마다 독립적으로 앙상블했습니다.

## 구조: 3단계 깔때기
```
질문 8,000개 × 이미지 16,000장
 │
 ├─ [1단계] SigLIP Base (A 학습본, fp16)
 │     코사인 유사도 → 질문마다 상위 k1장 (첫 제출 k1=15)
 │
 ├─ [2단계] BLIP-2 ITM (A 학습본, int8 저장 → 로드 시 복원)
 │     k1장 전부 채점 → 질문별 z-점수로 1단계와 합산 (blip_weight 0.9)
 │
 └─ [3단계] Qwen3-VL-Reranker-2B + LoRA (C 학습본, int8, 프롬프트 없음, 256px)
       1·2위 점수 차가 작은(헷갈리는) 질문부터 상위 k3장 재판정 (k3=3)
       → 질문별 z-점수로 합산 (qwen_weight 0.5) → 최종 top-5
```

### 규칙 준수
- 모든 정규화는 **질문 하나 안에서만** 합니다(다른 질문 정보 사용 없음).
- CSV 병합 없음, 외부 API 없음, 생성형 AI 증강 없음.
- 저수준 가속(커스텀 CUDA 커널, bitsandbytes, compile) 사용 안 함. int8은 저장용이고, 로드할 때 원래 정밀도로 복원합니다.

## 시간 관리 (15분 제한)
| 장치 | 내용 |
|---|---|
| 한 번만 디코딩 | 이미지를 한 번 읽어서 224px(SigLIP/BLIP)과 256px(Qwen) 배열을 같이 만듦 |
| 2단계 마감 | `stage2_deadline`(600초)을 넘으면 BLIP-2 중단 |
| 1위권부터 처리 | 2단계는 1위 후보 이미지부터, 3단계는 헷갈리는 질문의 1·2위부터 처리 → 시간이 모자라도 중요한 칸이 먼저 채워짐 |
| 부분 재정렬 | 질문마다 **앞에서부터 빠짐없이 채점된 칸까지만** 재정렬, 나머지는 1단계 순서 유지 |
| 전체 마감 | `time_limit`(840초, predict 시작 기준)에 Qwen 중단 |

### A K=20 제출이 떨어진 원인과 고친 점
A K=20 제출은 0.2319로 떨어졌습니다 (A K=5는 0.3275).
- A 코드는 시간 예산이 `load_model` 시작부터 720초였습니다.
- 20칸 중 하나라도 채점이 안 된 질문은 **통째로** 1단계 순서를 썼습니다.
- 이미지를 번호순으로 처리했습니다.
- 그래서 K=20이면 거의 모든 질문이 미완료가 되어 사실상 SigLIP 단독이 됐습니다. CSV를 보면 A K=5와 top-5 묶음이 99.9% 같고, 순서만 SigLIP 쪽이었습니다.

앙상블 코드는 위 표의 "1위권부터 처리 + 부분 재정렬"로 이 문제를 피합니다.

## 용량 (제출 zip ≤ 5GB, 압축 전·후 모두)
| 구성 | 크기 |
|---|---|
| SigLIP Base fp16 | 0.41GB |
| BLIP-2 int8 | 1.29GB |
| Qwen LoRA int8 | 2.17GB |
| 합계 (zip) | **3.87GB** |

## 로컬 검증 (팀 clean 304 질문 × 후보 4,000장)
A 무작위 분할 valid ∩ C 그룹 분할 valA∪valB, Kaggle T4.

| 버전 | score | R@1 | R@5 |
|---|---|---|---|
| A K=20 (A 원본 코드) | 0.6984 | .579 | .987 |
| 앙상블 K=20 fp16 | 0.7930 | .717 | – |
| **앙상블 K=15 / 840초 int8 (첫 제출)** | **0.8022** | **.730** | .987 |

- A K=20 대비 +0.0946 [95% CI +0.0655, +0.1241], 질문별 47승 5패.
- 서버 출력 형식 검사 통과.
- **주의:** A 모델은 무작위 분할로 학습해서, 이 검증 질문의 형제 이미지를 학습 때 이미 봤습니다. 그래서 로컬 점수는 부풀려져 있고, 테스트(16,000장)는 훨씬 낮게 나옵니다(지금까지 팀 제출 0.23~0.33). 판단은 리더보드 점수로 합니다.
- T4에서는 Qwen이 bf16을 지원하지 않아 느렸습니다(2.37초/쌍). 서버 L4는 bf16을 지원해 약 20ms/쌍입니다.

## 설정 바꾸는 법
zip의 `models/ens_config.json`만 바꾸면 됩니다 (`model.py`의 `DEFAULT_CFG`를 덮어씀).

| 키 | 뜻 | 첫 제출 |
|---|---|---|
| `k1` | 1단계 후보 수 | 15 |
| `blip_weight` | BLIP-2 점수 비중 | 0.9 |
| `k3` | Qwen이 다시 보는 후보 수 | 3 |
| `qwen_weight` | Qwen 점수 비중 | 0.5 |
| `stage2_deadline` | BLIP-2 마감(초) | 600 |
| `time_limit` | 전체 마감(초) | 840 |
| `rr_res` | Qwen 입력 해상도 | 256 |

## 만들기
```
python tools/build_ens.py --out sub_ens --siglip <A models/> --blip <A reranker/> --qwen <C models/reranker/> \
    --blip-q8 --siglip-fp16 \
    --config '{"k1":15,"k3":3,"blip_weight":0.9,"qwen_weight":0.5,"time_limit":840,"stage2_deadline":600}' --zip
```
